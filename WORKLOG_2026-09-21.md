## 1. What was actually broken

**"Update results" did nothing, and it could never have worked.** The Settle button could only
settle what `RACINGTV_2023_2026.dbo.Scraped_Results` already held — and that table is filled by
`scripts/racingtv_db_updater.py`, a Playwright scraper of `racingtv.com/results/<date>` that nobody
had run since **19 September**. On the 21st the table still stopped at the 19th, so **20 September had
no results at all** and Settle reported zero. Betfair cannot fill that gap: its Exchange API serves
live markets only — asking it for a finished day returns **0 markets** (verified directly).

**The app was also serving stale data.** The Streamlit process had been running since **20 Sep 08:54**,
so it showed the ledger as it stood *before* the settle ("54 logged bet(s) have no result yet") and
did not contain the new panel at all. Fixed by `R` / ⋮ → Rerun, or restarting the app.

**Two year-old price outliers were reaching the UI.** `bf_odds` up to **1000** and `bf_place_odds` up
to 250 (Betfair's ladder *caps* at 1000, so a captured 1000 means "no offer"). The AI System's BSP
figure read **+851%** off a single row because of one.

**A caption in the app was wrong.** The forward book's note claimed its two P/L columns "cannot both
be right". They can — see §3 below — and that line should be replaced.

## 2. What was built

| file | what it does |
|---|---|
| `cloud_app/price_snapshot.py` | new `betfair_price_snapshots` table in `racing_form.db`: one row per runner per capture (back, lay, ltp, volume, source). Hourly via `--hourly` (idempotent, so a 30-minute timer yields exactly hourly rows); on demand via the button; `--backfill-from/--backfill-to` pours in what SQL Server already holds |
| `cloud_app/results_refresh.py` | the chain the button needs: scrape → sync → settle, for any date, any time of day. Refuses to scrape a race **less than `--min-age-minutes` (default 30) past its off**, because a partly-loaded result page would be stored and never revisited |

| Task Scheduler **"Race results auto update"** | every 15 minutes **while the user is logged on**, so it is on when the laptop is open and stops when it is shut. Windows will not start a second copy while one runs, so runs cannot stack |
| `cloud_app/app.py` — 🔁 panel | **⚡ Update results now** · **🔄 Re-scrape day (force)** · **📸 Capture Betfair prices**, each printing its steps so a failure is visible instead of silent |
| `cloud_app/settle_daily_results.py` | `force=` (re-check already-settled rows; a row whose scrape is silent is left untouched), `clean_price` range check on every price at write time, and `price_flag` marking scraped-SP vs BSP disagreements above 50% |
| `cloud_app/app.py` — `price_ok` | range guards on all five paths a Betfair price enters a map |
| `scripts/hist_steam_drift.py` | historical steam/drift + hedge-trade test, 497,345 runners |
| `scripts/price_move_model.py` | offline price-move model (nothing in the site) |

## 3. What was measured (numbers live in the findings file)

* **Steam/drift, 497,345 runners, 5.75 years** — a price-band effect (42% of 1–3 shorten, 28% of 25+),
  not a selection signal, and not tradeable: the hedge loses on every rule except Big Weight Drop, at
  **+1p a £2 trade**. Waiting for BSP beats the morning *exchange* price by 8.4pp.
* **The forward book, taken apart** (`our_system_forward_ledger.csv`, 1,759 real bets):
  **+39.9% at the price taken, +7.0% at BSP**, and **all 1,759 rows have a matched BSP** — so the
  app's "cannot both be right" line is obsolete. The two figures coexist because on the **winners** he
  averaged **9.64 taken against 7.45 BSP**, while on the losers BSP was longer (17.68 vs 14.98), which
  costs nothing. Split: Each-Way 1,151 bets +39.6% / +3.5% · Win Only 608 +40.8% / +15.4%.
  Strike beats the market's implication by **+4.3pp at his prices** and **+1.1pp at BSP** — a selection
  edge *and* a price edge.
* **Price-move model** — AUC 61.8 out-of-sample, honestly calibrated, top decile **+£0.24 per £2
  trade** surviving ~10% of execution cost, and it sorts the rule picks (+£0.21 vs −£0.24 per trade on
  Big Weight Drop). It is a value model in movement's clothing: RPR and rating carry it, the price
  barely helps.
